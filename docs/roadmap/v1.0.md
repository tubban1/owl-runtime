# OWL Runtime Roadmap to 1.0

Current release candidate: **1.0.0-rc.2**.

Target: **1.0.0-rc.2**, then **1.0.0** after dogfood and soak.

The feature surface is now locked. See [1.0 Scope Lock](1.0-scope-lock.md) and the normative [1.0 Frozen Baseline](1.0-frozen-baseline.md). New product features do not enter 1.0 unless they fix correctness, security, recovery, cancellation, ownership/isolation, public-contract compatibility, or production reliability.

## Already complete

- standalone production Runtime daemon, independent of MCP;
- local RuntimeClient / HTTP public API v0.1;
- stable logical session identity across requests;
- reconnect-safe process control capability;
- request cancellation propagated to shell process groups;
- persistent Tasks, Scheduler, Loop, staging, existing memory contracts;
- workspace ownership / Resource Arbiter / concurrency;
- state schema / migrations / candidate upgrade / rollback;
- Observation ABI;
- Verifier ABI;
- File postcondition verification;
- Browser postcondition baseline;
- Managed Process state machine;
- one-time Approval receipts;
- Execution Health model;
- production install/upgrade/rollback verification;
- recovery and concurrency matrices.

## Remaining 1.0 work packages

### 1. ExecutionTarget / Provider Affinity — DONE

- [x] public `host | sandbox | remote` contract;
- [x] host implemented;
- [x] sandbox/remote fail closed;
- [x] silent fallback forbidden;
- [x] provider affinity constraint;
- [x] Persistent Task target durability;
- [x] Schedule target durability;
- [x] conformance verifier.

Production sandbox and remote execution are explicitly post-1.0.

### 2. Provider Observation / Verification closure — DONE

- [x] File;
- [x] Process;
- [x] Browser deterministic postconditions where machine-verifiable;
- [x] Browser generic/submit side effects fail closed as `uncertain` unless an explicit semantic postcondition is supplied;
- [x] Browser request cancellation interrupts pending operations and provider recovery is verified;
- [x] Desktop clipboard mutation has deterministic verification;
- [x] Desktop generic input actions fail closed as `uncertain` rather than treating input delivery as business success;
- [x] provider permission problems surface through Health / Needs Attention.

### 3. Diagnostics / support package — DONE

- [x] version/platform/runtime mode;
- [x] provider and permission status;
- [x] state schema;
- [x] Task / Process / Lease summaries;
- [x] recent errors/audit summary;
- [x] secret/content redaction;
- [x] machine-readable export through RuntimeClient / HTTP.

### 4. Release evidence — RC GATE READY

- [x] consumer RuntimeClient conformance;
- [x] production install/upgrade/rollback;
- [x] focused concurrency/recovery matrices;
- [x] auditable RC-fast gate passed on the pre-promotion commit;
- [x] 30-second smoke soak passed with no leaked Tasks/processes/leases or duplicate Scheduler/Loop side effects;
- [ ] real 2-hour soak passed;
- [ ] real 6-hour soak passed;
- [ ] real 24-hour soak passed;
- [ ] `1.0.0-rc.2` dogfood;
- [ ] fresh-machine setup verification;
- [ ] final `1.0.0` release gate.

The RC version commit must itself pass `npm run verify:rc`; no tracked changes should be made after that evidence is recorded unless the gate is rerun on the new SHA.

## Release sequence

```text
0.10.0-dev.0
  ↓ remaining hardening only
1.0.0-rc.2
  ↓ consumer/personal dogfood + soak
1.0.0
```

Do not create new pre-1.0 feature milestones merely to accommodate scope expansion.
