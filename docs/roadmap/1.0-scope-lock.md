# OWL Runtime 1.0 Scope Lock

Status: **normative**.

Current release candidate: `1.0.0-rc.4`.

OWL Runtime is now in the **`1.0.0-rc.4` stabilization phase**. The 1.0 feature surface is frozen; only release-blocking correctness, security, recovery, cancellation, ownership/isolation, compatibility, or measurable production-reliability fixes may enter before `1.0.0`.

## 1.0 purpose

OWL Runtime 1.0 is a reliable local execution runtime that can be consumed by `computer-mcp`, `owl-worker`, CLI tools, and future adapters through a stable public contract.

1.0 is not a complete AgentOS, enterprise control plane, remote orchestration system, or universal app-automation catalog.

## Remaining work packages

Only these four work packages may block `1.0.0-rc.4`:

1. **ExecutionTarget / Provider Affinity**
   - explicit `host | sandbox | remote` execution target contract;
   - host implemented now;
   - sandbox/remote represented honestly as unavailable unless a provider exists;
   - no silent target fallback for side effects.

2. **Provider Observation / Verification closure**
   - File complete;
   - Process complete;
   - Browser/Desktop deterministic postconditions for the supported 1.0 operations;
   - provider permission failures surface as Health/Needs Attention.

3. **Diagnostics / support package**
   - version, platform, providers, permissions, state schema, task/process/lease summaries, recent errors;
   - secret/token/content redaction;
   - machine-readable export for support and bug reports.

4. **Release evidence**
   - consumer conformance for RuntimeClient;
   - production install/upgrade/rollback;
   - multi-session concurrency/recovery;
   - real 2h, 6h, and 24h soak passes;
   - `1.0.0-rc.4` dogfood before `1.0.0`.

## Explicitly NOT blocking 1.0

- a production sandbox implementation;
- remote execution fleet/orchestrator;
- Kubernetes integration;
- enterprise multi-tenant control plane;
- billing/licensing;
- new social/app-specific adapters;
- general-purpose planner/LLM inside Runtime;
- autonomous skill synthesis;
- trajectory learning;
- extra memory features beyond the current Runtime contract;
- zero-downtime traffic proxy;
- cross-Runtime live Task migration;
- UI/product features that belong to `owl-worker`;
- MCP compatibility behavior that belongs to `computer-mcp`.

These belong to `1.1+`, `2.0+`, or consumer repos unless a proven 1.0 reliability defect requires otherwise.

## Change rule

A new proposal may enter 1.0 only if it fixes one of:

- correctness;
- data loss;
- security;
- recovery;
- cancellation;
- ownership/isolation;
- stable public contract compatibility;
- measurable production reliability.

Everything else goes to backlog.

## Promotion path

```text
0.10.0-dev.0
   ↓ four work packages complete
1.0.0-rc.4
   ↓ personal/consumer dogfood + soak
1.0.0
```

No automatic production promotion is implied by a Git commit or development release.
